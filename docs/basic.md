# PX-65 BASIC 説明書

日本語 | [English](basic.en.md)

PX-65の内蔵ROMに入っているBASICです。浮動小数点、三角関数・指数・対数、文字列関数、グラフィック、音、テープへの名前付き保存が使えます。

![起動画面](basic.png)

- ROMの `$A000-$DFFF`(16KBのうち約14.3KBを使用)にあり、モニター(`$E000-$FFFF`)のBIOSを使う
- 既存のBASIC(Microsoft BASICなど)のコードは使わず、すべて新しく書いた。命令の名前や書き方は、よく知られたBASICに合わせてある

## 起動と画面

```
PX-65 BASIC 0.11
30717 BYTES FREE
>
```

- 電源を入れるとBASICが起動する。プロンプトは `>`(モニターは `*`)
- 行番号(0〜63999)を付けて打つとプログラムに入る。付けずに打つとすぐ実行する(直接実行)。行番号だけを打つと、その行を消す
- 1行は58文字まで。← → でカーソルを動かし、打った文字はカーソルの位置に入る。DEL でカーソルの前の1文字を消す。↑ で直前の行を呼び出す。RET を押すと、カーソルがどこにあっても行全体を確定する(`EDIT` と `INPUT` でも同じ)
- 打った行は大文字と小文字を区別しない(`print` も `PRINT` になる)。`" "` の中はそのまま
- BREAKキー(PCでは Esc)で、実行中のプログラムを止める(`BREAK IN 120`)。INPUT や LIST のキー待ち、RENUM の知らせのキー待ちのときも止まる。入力中なら、その行を取り消す
- リセットしてもプログラムは消えない(変数は消える)。エミュレーターの「電源を切ってもRAMを残す」は初めからオンなので、電源を切って入れ直しても、ページを開き直しても、プログラムは残る(変数は消える。実行の途中から続きを始めることはない)。オフにすると、電源を入れるたびに消える。プログラムも変数も全部消したいときは「RAMを消去」を押す
- 液晶の DEG / RAD は角度の単位、RUN はプログラムを実行しているあいだ(INPUT で入力を待っているときも)、BUSY はテープを使っているあいだ点く。SHIFT は SHIFT が効いているあいだ点く。PRO、CAPS、LOW はこの BASIC では使わない(プログラムを打つモードと実行するモードの区別、大文字と小文字の切り替え、電池がないため)

### 記号の打ち方

画面のキーでは、SHIFT を押してから、キーの右上に小さく書いた文字のキーを押して出します(SHIFT は次の1文字だけ効きます。「SHIFTは次の1文字だけ」のチェックを外すと、押している間だけ効く方式になります)。BASICでよく使う記号は次のとおりです。PCのキーボードからは、記号をそのまま打てば入ります。

| 記号 | `:` | `;` | `^` | `"` | `$` | `(` `)` | `<` `>` | `?` |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| キー | SHIFT+`×` | SHIFT+`+` | SHIFT+`=` | SHIFT+`2` | SHIFT+`4` | SHIFT+`8` `9` | SHIFT+`,` `.` | SHIFT+`÷` |

## 数と式

- 数は5バイトの浮動小数点(指数8ビット、仮数32ビット)。有効数字は約9.6桁で、表示は9桁まで。範囲は約 ±1.7E38、0でない最小の絶対値は約 2.9E-39(それより小さくなると0)
- 表示: `PRINT 1/3` → ` .333333333`、`PRINT 2^40` → ` 1.09951163E+12`、`PRINT .0001` → ` 1E-04`。数の前には符号の場所(正なら空白)、後ろには空白を1つ出す
- 書き方: `123`、`1.5`、`.5`、`1E-3`、`&H7F`(16進数。0〜FFFF。DATA の中や INPUT で打つときも使える)
- 演算子(優先順位の高い順):

| 優先順位 | 演算子 |
| --- | --- |
| 1 | `( )`、関数 |
| 2 | `^`(べき乗) |
| 3 | 単項の `-` |
| 4 | `*` `/` |
| 5 | `+` `-` |
| 6 | `=` `<>` `<` `>` `<=` `>=`(真は -1、偽は 0) |
| 7 | `NOT` |
| 8 | `AND` |
| 9 | `OR` |

- `AND` `OR` `NOT` は、-32768〜65535 の整数にしてからビットごとに計算する
- `^` は、指数が整数(絶対値32767以下)なら、かけ算をくり返して計算する。ちょうど表せる答えはちょうどになる(`2^10` は1024、`(-2)^3` は -8)。ただし、指数の絶対値が32を超え、底が整数でも2のべき(0.5、1024 など)でもないときは、かけ算をくり返すと誤差がたまるので、`EXP(y*LN(ABS(x)))` で計算する(x が負で指数が奇数なら負にする。`1.0001^10000` は ` 2.71814131`)。指数が整数でないとき、または指数の絶対値が32767を超えるときも `EXP(y*LN(x))` で計算し、x が負ならエラー(`(-1)^32768` も `?FC ERROR`)
- 文字列は `+` でつなぐ。比較もできる(`A$<"M"`。文字コードの順)

## 変数と配列

- 名前は英字で始まり、英字と数字が続く。区別するのは最初の2文字(`COUNT` と `CO` は同じ変数)。命令の名前を含む名前(`TOTAL` は `TO` を含む)は使えない
- `A` は数、`A$` は文字列(255文字まで)
- `DIM A(20)`、`DIM B$(5,5)`。添字は0から。`DIM` しないで使うと、各次元10までの配列になる
- `RUN`、`NEW`、`CLEAR`、`LOAD`、プログラムの行を変えたとき、リセットしたときに、変数はすべて消える
- `MON` でモニターに入って `Q` で戻ったときは、変数は残る(モニターでメモリを書き換えて、BASIC のメモリの使い方の記録が壊れていたときだけ消える)。FOR や GOSUB の途中は残らないので、`CONT` はできない

## 命令

1行に `:` で区切って複数の命令を書けます。

### プログラムの編集と実行

| 命令 | 書き方の例 | 内容 |
| --- | --- | --- |
| NEW | `NEW` | プログラムと変数を消す |
| LIST | `LIST`、`LIST 100`、`LIST 100-200`、`LIST 100-`、`LIST -200` | プログラムを表示する。画面がいっぱいになるとキーを待つ(RET、↓、空白で続き、ほかのキーで終わり) |
| RUN | `RUN`、`RUN 100` | 変数を消して実行する |
| CONT | `CONT` | STOP や BREAK で止まったところから続ける |
| EDIT | `EDIT 100` | 100行を入力行に出す。直して RET を押すと書き換わる |
| DELETE | `DELETE 100`、`DELETE 100-200` | 行を消す |
| RENUM | `RENUM`、`RENUM 100,5`、`RENUM 1000,10,500` | 行番号を振り直す(下を参照) |
| CLEAR | `CLEAR` | 変数を消す |
| MON | `MON` | モニターに入る(モニターの `Q` で戻る。プログラムと変数は残る。CONT はできない) |
| CALC | `CALC` | 計算モードにする(下を参照) |

### RENUM

`RENUM [新しい開始番号[,増分[,元の開始番号]]]`。元の開始番号以降の行を、新しい開始番号から増分おきに振り直します。省くと `10,10,0`(すべての行を10から10おき)です。途中を省くときはカンマだけを書きます(`RENUM ,,500` は500行以降を10から10おきに。ただし、前の行と順番が入れ替わるならエラー)。

```
>LIST
5 INPUT N
7 IF N<0 THEN 5 ELSE GOSUB 12
9 GOTO 5
12 PRINT SQR(N):RETURN
>RENUM 100,10
>LIST
100 INPUT N
110 IF N<0 THEN 100 ELSE GOSUB 130
120 GOTO 100
130 PRINT SQR(N):RETURN
```

- `GOTO` `GOSUB` `THEN` `ELSE` `RUN` `RESTORE` の後ろの行番号と、`ON 〜 GOTO` / `ON 〜 GOSUB` の並びの行番号も新しい番号に書き換える。`" "` の中、`REM` と `DATA` の中は変えない
- ない行への参照(`GOTO 999` で999行がないなど)はそのまま残し、`UNDEF 999 IN 30` の形で知らせる。`999` は書いてあるとおりの番号、`30` はその参照がある行の新しい番号。元の開始番号より前の行への参照は、その行があれば変えずに何も出さない
- 知らせが画面に入りきらないときは、3行出すとキーを待つ。RET、↓、空白で続きを出し、ほかのキーで残りの知らせを出さずに振り直す。このキー待ちのときに BREAK を押すと、何も変えずに RENUM をやめる
- 知らせが3行までなら、キーを待たずにそのまま振り直す(やめる機会はない)。振り直した後で知らせを見て、参照を直す

```
>RENUM
UNDEF 999 IN 30
>
```

- 振り直すと前の行と順番が入れ替わる、番号が63999を超える、増分が0のときは、何も変えずに `?FC ERROR`
- 行番号の桁が増えてプログラムが入らないときは、何も変えずに `?OM ERROR`。振り直す行の数×2バイトの空きを作業に使う
- 振り直した後は変数が消える。プログラムの中で使うと、振り直した後に止まる
- `LIST` `EDIT` `DELETE` の後ろの行番号(プログラムの中に書いた場合)は書き換えない
- かかる時間の目安: 100行で約0.7秒、500行で約4秒

LIST は `?` を `PRINT`、`'` を `REM` として表示します。詰めて打った行は、読みやすいようにキーワードの前後に空白を足して表示します(`?1` は `PRINT 1`、`IFA>0THEN100` は `IF A>0 THEN 100`)。`SIN(1)` のような関数と `(` の間は詰めたままです。プログラムの中身は変わりません。

EDIT でも同じ形で入力行に出します。ただし、空白を足すと58文字に入りきらない行は、打ったときのまま(詰めた形)で出します。空白を足した形で RET を押すと、その空白もプログラムに入ります。

### CALC(計算モード)

`CALC` と打つと計算モードになり、プロンプトが `>` から `C>` に変わります。計算モードでは、式を打って RET を押すだけで答えが出ます(`PRINT` は要りません)。

```
>CALC
C>1+2
 3
C>R=5
C>PI*R^2
 78.5398163
C>DEG
C>SIN(30)
 .5
```

計算モードでは、打った行を次のように扱います。

| 打った行 | 扱い | 例 |
| --- | --- | --- |
| 式 | 値を表示する(`PRINT` と同じ形) | `1+2`、`SQR(2)`、`-5*3`、`"AB"+"C"` |
| 数で始まる行 | 式。計算モードではプログラムの行は打てない | `100/7` |
| `変数=式` | 代入する(何も表示しない) | `R=5`、`A(3)=7`、`A$="X"` |
| 命令で始まる行 | ふつうの直接実行と同じ | `DEG`、`?1;2`、`LIST`、`RUN` |
| 空の行 | 何もしない | |

- 等しいかどうかを調べるときは、`(A=5)` のように括弧で囲みます(`A=5` は代入になる)。`A<5` などはそのまま書けます
- 式として扱うのは、行の最初の文だけです。`:` の後に続ける式には `?`(PRINT)を付けます(`A=2:?A+3`、`1+2:?3+4`)
- `EDIT` で直した行は、計算モードでもいつもの行として扱います(行番号があればプログラムに入り、行番号を消すとふつうの直接実行)。終わると `C>` に戻ります。編集中に BREAK を押すと、編集を取り消して `C>` に戻ります(計算モードは終わらない)
- エラーが出ても計算モードのままです。`RUN` でプログラムを動かしても、終わると `C>` に戻ります
- `C>` で入力を待っているときに BREAK(PCでは Esc)を押すと、計算モードが終わって `>` に戻ります。プログラムの実行中の BREAK は、プログラムを止めて `C>` に戻ります
- リセット、電源の入れ直し、`MON` から `Q` で戻ったときも、計算モードは終わります
- 前の答えを使いたいときは、`X=式` のように変数に入れておきます
- プログラムの中に書いた `CALC` は、プログラムが終わった後に計算モードにします

### 流れ

| 命令 | 書き方の例 | 内容 |
| --- | --- | --- |
| END / STOP | | 終わる / 止める(`BREAK IN 100` を出す。CONT で続けられる) |
| REM / `'` | `REM メモ`、`' メモ` | 注釈(行の終わりまで) |
| GOTO / GOSUB / RETURN | `GOTO 100`、`GOSUB 1000` | 飛ぶ、サブルーチン |
| ON | `ON N GOTO 100,200,300` | Nの値(1, 2, …)で飛び先を選ぶ。N は小数点以下を切り捨てる(-0.5 は 0)。0 か、飛び先の数より大きければ次の命令へ。切り捨てた値が負か 256 以上なら `?FC ERROR`。GOSUB も可 |
| IF | `IF A>0 THEN 100`、`IF A THEN PRINT A ELSE PRINT "NO"`、`IF A>0 GOTO 100` | 条件。THEN の後に行番号か命令。偽なら ELSE の後(なければ次の行)へ。IF の中に IF を書いたときは、ELSE はいちばん近い、まだ ELSE のない IF のものになる(`IF A THEN IF B THEN PRINT 1 ELSE PRINT 2` の ELSE は2つ目の IF のもの。A が偽なら何もしない) |
| FOR / NEXT | `FOR I=1 TO 10 STEP 2` … `NEXT I` | 繰り返し。NEXT の変数は省ける。`NEXT J,I` も可 |

### データ

| 命令 | 書き方の例 | 内容 |
| --- | --- | --- |
| LET | `LET A=1`、`A=1` | 代入(LET は省ける) |
| DIM | `DIM A(10),B$(3,4)` | 配列 |
| DATA / READ / RESTORE | `DATA 1,2,"A"`、`DATA &HA2,&H41`、`READ A,B,C$`、`RESTORE`、`RESTORE 100` | データ。数には16進数(`&H`)も書ける |
| POKE / CALL | `POKE &H600,169`、`CALL &H600` | メモリに書く、機械語を呼ぶ(RTS で戻る) |

### 入出力

| 命令 | 書き方の例 | 内容 |
| --- | --- | --- |
| PRINT / `?` | `PRINT A;B$,C`、`PRINT TAB(5);"X";SPC(2);"Y"` | 表示。`;` で続けて、`,` で次の8桁の区切りへ。最後に `;` か `,` があると改行しない |
| INPUT | `INPUT A`、`INPUT "NAME";N$`、`INPUT A,B` | キーボードから入れる(`? ` を出して待つ)。数のところに数でないものを打つと `?REDO` で入れ直し。足りないと `?? ` で続きを聞く。直接実行ではエラー |
| CLS | `CLS` | 画面を消す |
| LOCATE | `LOCATE 0,3` | 文字の表示位置(桁 0〜15、行 0〜3) |
| WAIT | `WAIT 64` | 待つ(1/64秒単位。BREAK で止まる) |
| BEEP | `BEEP`、`BEEP 440`、`BEEP 880,50` | 音。周波数(Hz)、長さ(1/100秒、小数も可)。省くと 1000Hz で 0.1秒。周波数は小数点以下を切り捨てた値が 20〜20000。長さは 0 以上で、周波数 × 長さ ÷ 50(音の半周期の数)の小数点以下を切り捨てた値が 65535 以下であること。それ以外は `?FC ERROR`。長さの上限は周波数で変わる(1000Hz なら整数で 3276 = 約33秒まで)。小数の計算には丸めが入るので、上限ぎりぎりの指定は避ける |
| DEG / RAD | | 三角関数の角度の単位(度 / ラジアン)。液晶の DEG / RAD が点く。初めは RAD |
| RANDOMIZE | `RANDOMIZE` | 乱数の種をタイマーから決める(`RND(0)` が返す最後の値は変えない) |

INPUT の答えの読み方:

- 項目は `,` で区切る。多すぎる項目は読み捨てる。何も打たずに RET を押すと、`?? ` でもう一度聞く(空白だけの行は、空の答えとして読む。数の変数なら 0、文字列の変数なら空の文字列になる)
- 数は、先頭と途中の空白を飛ばして読む(`1 2` は 12)。`&H` の16進数も使える。数の後に `,` か行の終わり以外の文字があると `?REDO`
- 文字列は、`"..."` で囲むと `,` や `:` も入れられる(囲んだ後に `,` か行の終わり以外の文字があると `?REDO`)。囲まないときは、先頭の空白を飛ばして、`,` か `:` の手前までが文字列(後ろの空白は残る)
- 引用符の外の `:` は、行の終わりとみなす。`:` より後ろは読まず、変数が残っていれば `?? ` で続きを聞く

### グラフィック

画面は 96×32 ドット。左上が (0,0)、右下が (95,31) です。座標は小数点以下を切り捨て、-1024〜1023 の範囲で書けます(それを超えると `?FC ERROR`)。この範囲で画面の外にある点は描かれません(線や円の一部が外に出てもかまいません)。文字とグラフィックは同じ画面に重なります。

| 命令 | 書き方の例 | 内容 |
| --- | --- | --- |
| PSET / PRESET | `PSET 10,5`、`PSET 10,5,2`、`PRESET 10,5` | 点を描く / 消す。3つ目は 1 描く、0 消す、2 反転 |
| LINE | `LINE 0,0,95,31`、`LINE 0,0,95,31,0` | 線(最後は PSET と同じ) |
| CIRCLE | `CIRCLE 48,16,10`、`CIRCLE 48,16,10,2` | 円(中心、半径。最後は PSET と同じ) |

### テープ

| 命令 | 書き方の例 | 内容 |
| --- | --- | --- |
| SAVE | `SAVE "GAME"` | プログラムをテープの最後に足して保存する。名前は8文字まで(省くと空白の名前) |
| LOAD | `LOAD "GAME"`、`LOAD` | その名前のプログラムを読み込む(同じ名前がいくつかあれば最後のもの)。名前を省くと最初のプログラム。変数は消える |
| FILES | `FILES` | テープの中身の一覧(`B` はプログラム、`M` はモニターの W で保存したメモリ。名前と長さ) |

```
>FILES
B GAME     312
M SPRITE   256
```

- 保存はいつもテープの最後に足します。テープを空にするには、エミュレーターの「テープを取り出す」で取り出して、新しいテープにします(テープを入れていなければ、保存すると新しいテープができます)
- 同じ名前で何度か保存すると、テープには全部が残り(`FILES` に全部が出る)、`LOAD "名前"` はいちばん後ろ、つまり最後に保存したものを読みます
- テープには全部で65,536バイトまで入ります。入りきらないときは `?TF ERROR` になり、テープは保存する前のまま残ります
- テープはエミュレーターの「テープを保存」でファイルにでき、「テープを入れる」で戻せます

## 関数

| 関数 | 内容 |
| --- | --- |
| `ABS(x)` `SGN(x)` `INT(x)` | 絶対値、符号(-1, 0, 1)、x以下の最大の整数(`INT(-3.7)` は -4) |
| `SQR(x)` | 平方根 |
| `SIN(x)` `COS(x)` `TAN(x)` `ATN(x)` | 三角関数(角度は DEG / RAD による) |
| `EXP(x)` `LN(x)` `LOG(x)` | e^x、自然対数、常用対数(底10) |
| `PI` | 円周率(3.14159265) |
| `RND(x)` | 0以上1未満の乱数。x>0 で次の値、x<0 で x から種を決め直して最初の値、x=0 で最後に作った値。最後の値は RANDOMIZE、RUN、CLEAR、リセットでは消えない。RAMを消して起動してから、まだ作っていなければ 0 |
| `PEEK(a)` `FRE(0)` | メモリの値、空きバイト数 |
| `POINT(x,y)` | 点が点いていれば1、消えていれば0(画面の外は0。座標が -1024〜1023 を超えると `?FC ERROR`) |
| `LEN(s$)` `ASC(s$)` `VAL(s$)` | 長さ、最初の文字のコード、数に変換(数でなければ0) |
| `CHR$(n)` `STR$(x)` `HEX$(n)` | 文字、数を文字列に(正の数は先頭が空白)、16進数の文字列に |
| `LEFT$(s$,n)` `RIGHT$(s$,n)` `MID$(s$,p[,n])` | 部分文字列(位置は1から) |
| `INSTR([p,]s$,t$)` | s$ の中の t$ の位置(なければ0)。p から探す |
| `INKEY$` | 押されたキー(なければ空の文字列)。待たない |
| `TAB(n)` `SPC(n)` | PRINT の中だけで使える。n桁目へ進む / n個の空白 |

`LOG` は常用対数です(Microsoft BASICの `LOG` は自然対数なので、移植するときは `LN` に直してください)。

## エラー

`?SN ERROR IN 120` の形で出します(直接実行なら `IN` 以降はなし)。

| 表示 | 意味 |
| --- | --- |
| SN | 書き方の間違い |
| OV | 数が大きすぎる |
| /0 | 0で割った |
| FC | 関数や命令に渡した値がおかしい(`SQR(-1)`、`CHR$(300)`、`SIN(1E10)` など) |
| UL | その行番号がない |
| OM | メモリが足りない、式やFOR・GOSUBが深すぎる |
| TM | 数と文字列の取り違え |
| BS | 配列の添字が範囲外 |
| DD | 同じ配列を2回 DIM した |
| LS | 文字列が255文字を超えた |
| NF | FOR のない NEXT |
| RG | GOSUB のない RETURN |
| OD | READ するデータがない |
| CN | CONT できない |
| ID | 直接実行できない命令(INPUT など) |
| NT | テープがない、見つからない |
| TP | テープのデータが壊れている |
| TF | テープがいっぱいで保存できない(テープは保存前のまま。新しいテープに替える) |

## プログラムの例

```
10 REM サインカーブ
20 CLS
30 FOR X=0 TO 95
40 PSET X,16-14*SIN(X*PI/48)
50 NEXT
60 LINE 0,16,95,16
```

```
10 REM 数あて
20 RANDOMIZE:N=INT(RND(1)*100)+1
30 INPUT "1-100";G
40 IF G=N THEN PRINT "OK!":BEEP 880,30:END
50 IF G<N THEN PRINT "UP" ELSE PRINT "DOWN"
60 GOTO 30
```

## 速さと制限

- 速さの目安(1MHz): 空の `FOR` ループが1秒に700〜1000回。`A=A+I*2` は1回約6ミリ秒。`SQR` `SIN` `EXP` などの関数は1回30〜50ミリ秒
- 計算の精度の目安。誤差は、数として持っている引数に対する答えのずれで、単位は ulp(仮数のいちばん下の1ビットが表す大きさ。答えの約 2.3E-10〜4.7E-10 倍)。テストで大量に確かめた目安で、すべての入力での保証ではない。答えが小さすぎて 0 になるときや、エラーになるときは除く: `SQR` はいつも最も近い値。`EXP` と `ATN` は 2 ulp 以内(度の `ATN` は 6 ulp 以内)、`LN` `SIN` `COS` は 4 ulp 以内、`LOG` と `TAN` は 5 ulp 以内(ラジアンの `SIN` `COS` `TAN` には、次の項目の誤差が加わる)。9桁の表示では、最後の桁が1ずれることがある程度。`^` をかけ算のくり返しで計算するときは、かけ算の回数に応じて誤差がたまる(指数が n なら、およそ 2 + 2 × `ABS(n)` ulp 以内。答えがちょうど表せるなら、ちょうど)。`EXP(y*LN(x))` で計算するときは、答えが大きい(または小さい)ほど誤差が増える(およそ 4 + 5 × `ABS(LN(ABS(答え)))` ulp 以内。答えが 1E30 くらいなら、下の2桁ほどがずれることがある)。打った数や `VAL` の読み取りは、9桁までなら 1 ulp 以内(10桁では 1.5 ulp 以内)。`PRINT` や `STR$` の表示は、最後の桁が1ずれることがある(読み取りも表示も、9桁までの整数はちょうど)
- `SIN` `COS` `TAN` の引数は、ラジアンなら絶対値が約 6.7E9 まで、度なら約 2.4E10 まで。それを超えると `?FC ERROR`(答えを正確に求められないため)。ラジアンでは、いちばん近い π/2 の倍数を引いてから計算するので、答えが 0 に近いときも、ふつうは桁が落ちない(`SIN(3.14138865)` は9桁とも正しい ` 2.04003536E-04`)。ただし、π/2 も有限の桁(約64ビット)で持つので、引数の絶対値 × 約2E-22 の絶対誤差が残る。答えが引数の約1E-12倍より小さい(引数が、答えが 0 になる角度にとても近い。`SIN` と `TAN` は π の倍数、`COS` は π/2 に π の倍数を足した角度)ときは、この誤差で下の桁がずれる(`SIN(680232721/2048)` は `-3.59863607E-10`。正しくは `-3.59863537E-10`。`TAN(680232721/2048)` も同じく ` 3.59863607E-10`)。引数が約 1700万(2^24)を超えると、π/2 の倍数を引くところにも誤差が入り、絶対誤差がおよそ 1E-9 以下になる。π は正確に表せないので、`SIN(PI)` は 0 ではなく、丸めた π に対する正しい値 ` 1.2154201E-10` になる(`SIN(3*PI)` は `-1.49801912E-09`)。`TAN` は、答えがとても大きいとき(COS が 0 に近い角度)にも誤差が大きくなる
- 度では 90 度ずつ正確に分けてから計算するので、90 度の倍数ではちょうどの値になる(`COS(90)` と `SIN(180)` は 0、`SIN(90)` は 1)。`TAN(90)` や `TAN(-90)` など、定義されない角度は `?/0 ERROR`
- これらの誤差や「ちょうどの値」は、数として持っている引数に対するもの。打った数が正確に表せない(約43億 = 2^32 を超える整数や、2進数で割り切れない小数)ときは、打ったときの丸めの分だけ答えがずれる。たとえば度で `SIN(18000000090)` は、引数が 18000000088 に丸められるので 1 ではなく `.999390827` になる。90度の近くの `COS(89.9999)` も、89.9999 の丸めのため、答えの相対誤差が約 1E-4 になる
- 行の中で使える `FOR` と `GOSUB` の深さは、CPUのスタック(256バイト)による。`FOR` は1つ17バイト、`GOSUB` は5バイト
- 文字列の領域がいっぱいになると、自動的に整理する(そのあいだ少し止まる)
- 行番号は0〜63999

## メモリの使い方

| 範囲 | 用途 |
| --- | --- |
| `$00-$7F` | 空き(機械語用) |
| `$80-$DF` | BASIC |
| `$E0-$FF` | モニター、BIOS |
| `$0100-$01FF` | CPUのスタック(FOR、GOSUB、式の計算にも使う) |
| `$0200-$02C5` | モニターのワークエリア |
| `$02C6-$02FF` | BASICのワークエリア(数学関数、グラフィック、BEEP、テープ) |
| `$0300-$037F` | 入力行(`$0300`、64バイト)と直前の行(`$0340`) |
| `$0380-$03FF` | BASICのワークエリア |
| `$0400-$057F` | VRAM |
| `$0580-$07FE` | 空き(機械語用。`CALL` で呼べる) |
| `$07FF` | BASIC が使う(いつも0。プログラムの直前の印) |
| `$0800-$7FFE` | プログラム、変数、配列、文字列(下から順にプログラム、変数、配列。文字列は上から) |
| `$7FFF` | BASIC が使う(`VAL` が文字列の直後を一時的に0にするときのため。文字列は置かない) |

プログラムは1行が `[次の行の番地(2)][行番号(2)][中身(キーワードは1バイトのトークン)][0]` の形で `$0800` から並び、最後は次の行の番地が0です。その直前の `$07FF` には0を置きます(`RUN` や `RESTORE` は、ここを前の行の終わりとみなして読み始めます)。`POKE` などで `$07FF` を0以外にすると、`RUN` が `?SN ERROR` になります。`NEW` や `LOAD` で0に戻ります。

## テープの形式

モニターと共通です。テープには複数のブロックを続けて記録できます。

| バイト | 内容 |
| --- | --- |
| 0-1 | `"PX"` |
| 2 | 種類。`$01` メモリ(モニターの W)、`$02` BASICのプログラム |
| 3-10 | 名前(8文字、足りない分は空白) |
| 11-12 | 開始番地(下位、上位) |
| 13-14 | 長さ(下位、上位) |
| 15- | データ |
| 最後 | チェックサム(それより前の、このブロックのすべてのバイトの和の下位8ビット) |

BASICのプログラムは `$0800` から保存し、読み込むときも `$0800` に置きます。
