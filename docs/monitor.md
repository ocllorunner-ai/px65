# PX-65 モニター

日本語 | [English](monitor.en.md)

PX-65の内蔵ROMに入っているモニターの説明書です。メモリを見る、書き込む、アセンブルする、プログラムを実行する、1命令ずつ実行して調べる、テープに保存する、といったことができます。

ソースは `rom/monitor.s`(共通の定義は `rom/px65.inc`)です。ROM(24KB)のうち `$E000-$FFFF` の8KBを使います(約6.7KB)。`$A000-$DFFF` の16KBにはBASIC(`docs/basic.md`)が入っています。

![起動した画面](monitor.png)

## 起動

内蔵ROMには BASIC が入っているので、電源を入れると BASIC が起動します。BASIC で `MON` と打つとモニターに入り、プロンプト `*` が出ます。モニターで `Q` と打つと BASIC に戻ります。プログラムと変数は残り、画面もそのままで、BASIC のプロンプト `>` が出ます(モニターでメモリを書き換えて BASIC のメモリの使い方の記録が壊れたときは、変数だけ消します)。リセットしたときは変数を消します。

`$A006` に `BASIC` という印がないROM(モニターだけのROM)では、電源を入れると `PX-65 MONITOR` `V0.11` と表示され、すぐにプロンプト `*` が出ます。

- **コールドスタート**(電源を入れたとき): ワークエリア、レジスタ、ブレークポイントを初期化します
- **ウォームスタート**(リセットしたとき、RAMを残す設定で電源を入れたとき): RAMの内容とブレークポイントはそのまま残ります。プログラムの実行中にリセットした場合も、メモリに書き込んであったBRK(ブレークポイント)は元に戻します

## 入力のしかた

- コマンドは1文字で、その後に引数を続けます。例: `D 600`、`E 600 A9 01`
- 数はすべて16進数で書きます。`$` は付けません。`0600` も `600` も同じです
- 引数の区切りは空白かカンマです。英字は大文字でも小文字でもかまいません
- 1行は58文字までです。画面の右端に来ると次の行に折り返します
- **←** **→** でカーソルを動かします。打った文字はカーソルの位置に入ります。**DEL** でカーソルの前の1文字を消します。**↑** で直前に入力した行を呼び出します。**RET** を押すと、カーソルがどこにあっても行全体を確定します
- **BREAK** で入力中の行や実行中のコマンドを取り消して、プロンプトに戻ります
- 間違った入力には `?` を表示し、ビープを鳴らします

SHIFTと組み合わせると次の文字になります。

| キー | A〜Z | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9 | 0 | , | . | ÷ | - | × | + | = |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| SHIFT+ | a〜z | ! | " | # | $ | % | & | ' | ( | ) | @ | < | > | ? | _ | : | ; | ^ |

矢印、SPACE、RET、DELはSHIFTを押しても同じです。エミュレーターの画面のキーには、SHIFTで出る文字を右上に小さく書いてあります。キーを0.5秒押し続けると、そのキーが繰り返し入力されます。

PCのキーボードからは、記号をそのまま打てば入ります(キーボードの配列によらず、打った記号になります)。

## コマンド一覧

| コマンド | 書式 | 内容 |
| --- | --- | --- |
| D | `D [番地]` | メモリダンプ |
| E | `E 番地 [値 ...]` | メモリに書き込む |
| F | `F 開始 終了 値 [値 ...]` | 範囲を値で埋める |
| M | `M 開始 終了 転送先` | メモリを転送する |
| S | `S 開始 終了 値 [値 ...]` | バイト列を探す |
| C | `C 開始 終了 比較先` | 2つの範囲を比べる |
| H | `H 値1 値2` | 和と差を計算する |
| U | `U [番地]` | 逆アセンブル |
| A | `A [番地]` | アセンブル(1行ずつ) |
| R | `R [レジスタ 値]` | レジスタの表示と変更 |
| G | `G [番地]` | 実行する |
| T | `T [回数]` | 1命令ずつ実行する |
| P | `P [回数]` | 1命令ずつ実行する(JSRはまとめて実行) |
| B | `B` / `B 番地` / `B - [番地]` | ブレークポイント |
| W | `W 開始 終了 ["名前"]` | テープに保存する |
| L | `L ["名前"] [番地]` | テープから読み込む |
| Q | `Q` | BASICに戻る(プログラムと変数は残る) |

「終了」の番地も範囲に含みます。「値」の並びには、16進数のほかに `"文字列"` も書けます。例: `E 700 "Hello" 0`

### D: メモリダンプ

```
*D 600
0600 A9 42 A2 07
0604 60 00 00 00
0608 00 00 00 00
060C 00 00 00 00
```

画面いっぱいに16バイトを表示して、キーを待ちます。

| キー | 動作 |
| --- | --- |
| ↓ / ↑ | 4バイト進む / 戻る |
| RET / SPACE | 16バイト進む |
| ほかのキー | 終わる。文字キーなら、それが次のコマンドの1文字目になる |

番地を省くと、前回の続きから表示します。

### E: メモリに書き込む

`E 600 A9 42 A2 07 60` のように値を並べると、その番地から順に書き込みます(16バイトまで)。

値を書かずに `E 600` とすると、1バイトずつ編集します。`0600 A9-` のように番地と今の値が出るので、新しい値を打ちます。

| キー | 動作 |
| --- | --- |
| 0〜9, A〜F | 値を入力する(2桁まで) |
| DEL / ← | 1桁消す |
| SPACE / ↓ | 書き込んで次の番地へ |
| ↑ | 書き込んで前の番地へ |
| RET | 書き込んで終わる |

何も打たずに次へ進めば、その番地は変わりません。

### F, M, S, C

- `F 600 6FF 0`: `$0600-$06FF` を0で埋めます。`F 600 6FF 1 2 3` のように並べると、その並びを繰り返します
- `M 600 6FF 1000`: `$0600-$06FF` を `$1000` からに写します。範囲が重なっていても正しく写します
- `S 600 7FFF A9 00`: `A9 00` が見つかった番地を、1行に3つずつ表示します
- `C 700 7FF 1000`: 違うバイトを `0705 12 1005 34` の形で1行ずつ表示します

### H: 和と差

```
*H 1234 100
1334 1134
```

### U: 逆アセンブル

```
*U 600
0600 LDA #42
0602 LDX #07
0604 RTS
0605 BRK
```

4行表示してキーを待ちます。**↓** で1行、**RET** か **SPACE** で4行進みます。ほかのキーで終わります(Dと同じ)。番地を省くと前回の続きからです。

数は `$` を付けずに表示します。`#42` は即値、`0400` は絶対番地、`(02),Y` は間接です。分岐命令は分岐先の番地を表示します。`BBR`/`BBS` の行だけは16文字を超えるので、次の行に折り返します。

### R: レジスタ

```
*R
A=42 X=07 Y=00
S=FF P=..-B....
0600 LDA #42
```

1行目がA、X、Y、2行目がスタックポインターとフラグ、3行目がPCの番地と、そこにある命令です。フラグは `NV-BDIZC` の順で、立っているものだけ文字を、立っていないものは `.` を表示します。

`R A 12`、`R X 0`、`R Y FF`、`R S FF`、`R P 0`、`R PC 600` のように書くと、そのレジスタを変えます。

### G: 実行

- `G 600`: `$0600` から新しく実行します。スタックポインターは `$FF` から始めます。プログラムが最後に **RTS** するとモニターに戻り、レジスタを表示します
- `G`: 止まったところ(PCの番地)から続けます。RTS でモニターに戻った後の `G` も、PC の番地(最後に止まっていた番地)から実行し、モニターへの戻り番地を新しく積みます。プログラムを初めからやり直すときは `G 600` のように番地を書きます
- どちらの場合も、PC の番地にブレークポイントがあれば、その命令を1つ実行してから、ブレークポイントを書き込んで続けます

実行中はBUSYのアナンシエーターが点きます。次のどれかでモニターに戻り、レジスタを表示します。

| 止まる理由 | PCの表示 |
| --- | --- |
| G で始めたプログラムが RTS した | (表示しない) |
| ブレークポイントに来た | ブレークポイントの番地(その命令はまだ実行していない) |
| プログラムの BRK 命令を実行した | BRKの2バイト後ろ |
| BREAK キーを押した | 次に実行する命令 |

### T, P: 1命令ずつ実行

`T` で1命令だけ実行してレジスタを表示します。`T 10` のように回数を書くと、その回数だけ実行してから表示します(`FF` 回まで)。

`P` は `T` と同じですが、JSR はサブルーチンから戻るまでまとめて実行します。

PCの番地を `R PC 600` などで決めてから使います。

次に実行する命令の行き先(分岐する命令なら、分岐する場合としない場合の両方)が `$00E0-$057F`(モニターとBIOSのゼロページ、スタック、作業領域、入力行、VRAM)のときは、その命令を実行せずにレジスタを表示し、`?` を出します。`T 10` などの途中なら、そこまで実行したところで止まります。P の JSR は、サブルーチンの中にBRKを書き込まないので、この場合も進められます。これらの番地には、1命令ずつ実行するためのBRKを書き込めないためです(モニターが使っている最中なので、書くとモニターが壊れます)。

### B: ブレークポイント

| 書き方 | 動作 |
| --- | --- |
| `B` | 一覧を表示する(なければ `-`) |
| `B 620` | `$0620` にブレークポイントを置く(4つまで) |
| `B - 620` | `$0620` のブレークポイントを消す |
| `B -` | 全部消す |

ブレークポイントは `$0000-$00DF` と `$0580-$7FFF` にだけ置けます。ほかの番地(`$00E0-$057F` と ROM)は `?` になります。`$00E0-$057F` はモニターが実行の準備をしている最中に使う番地なので、BRKを書き込むとモニターが壊れるためです。

`G` で実行している間だけ、その番地にBRK命令を書き込み、止まったら元に戻します。そのため、モニターでメモリを見ているときにBRKが見えることはありません。ブレークポイントは命令の先頭の番地に置きます。命令の途中やデータの番地に置くと、実行中はその1バイトがBRK($00)に変わるので、プログラムが正しく動きません。

ブレークポイントで止まった状態から `G` すると、その命令を1つ実行してから、ブレークポイントを書き込んで続けます。

置けない番地のブレークポイントが残っている場合(前の版で保存した状態を読み込んだときなど)、`G` は何も実行せずに `?` を出します。`B - 番地` で消してください。

### A: アセンブル

`A 600` とすると、`0600 ` と番地が出るので、命令を1行打ってRETを押します。命令を書き込み、次の番地が出ます。何も打たずにRETを押すと終わります。

```
*A 600
0600 LDA #41
0602 JSR FF00
0605 RTS
0606
*
```

- 書き方は `U` の表示と同じです。数は16進数で、`$` は付けても付けなくてもかまいません。英字は小文字でもかまいません
- オペランドの書き方: `#41`(即値)、`12`(ゼロページ)、`0400`(絶対番地)、`12,X`、`0400,Y`、`(12,X)`、`(12),Y`、`(12)`、`(1234)`、`(1234,X)`、`A`(アキュムレーター。`ASL` だけでもよい。アキュムレーターの形がない命令では、`A` は番地 `0A` として読む。`LDA A` は `LDA 0A`、`JMP A` は `JMP 000A`)
- オペランドを**2桁以下で書くとゼロページ、3桁以上で書くと絶対番地**になります。`LDA 0012` と書けば、値が小さくても絶対番地の命令になります。その命令にない方は、もう一方で代わりにします(`JMP 12` は `JMP 0012`)
- 分岐命令には分岐先の番地を書きます(`BNE 0600`)。届かないとエラーです
- `RMB`、`SMB`、`BBR`、`BBS` はビット番号を付けて書きます(`RMB3 12`、`BBS7 12,0620`)
- 間違えると `?` を表示してビープを鳴らし、同じ番地でもう一度入力できます。**↑** で直前に打った行を呼び出せるので、直してから RET を押します
- 番地を省くと、前回 `A` で書き終わった番地から続けます。`A` を終えた後の `U` は、`A` を始めた番地から表示します
- ラベルや `.byte` のような疑似命令はありません。データは `E` で書き込みます

### W, L: テープ

テープには複数のブロックを続けて記録できます。保存はいつもテープの最後に足します(前の中身は消えません)。テープを空にするには、エミュレーターの「テープを取り出す」で取り出します。

- `W 600 6FF "SPRITE"`: `$0600-$06FF` を `SPRITE` という名前でテープに保存し、`SAVE 0600-06FF` と表示します。名前は8文字まで(長ければ切り詰め)で、大文字と小文字を区別します。名前を省くと空白の名前になります
- `L "SPRITE"`: その名前のブロックを探して、保存したときと同じ番地に書き込み、`LOAD 0600-06FF` と表示します。同じ名前のブロックがいくつかあれば、いちばん後ろ(最後に保存したもの)を読みます
- `L`: 最初のメモリのブロックを読み込みます(BASICのプログラムのブロックは読み飛ばします)
- `L 1000`、`L "SPRITE" 1000`: 番地を書くと、そこへ読み込みます

読み込むと、PCを読み込んだ番地にし、次の `G` が新しく実行を始めるようにします。`L` の後は `G` だけで実行できます。`D` と `U` の続きの番地も、読み込んだ番地になります。

| 表示 | 意味 |
| --- | --- |
| `NO TAPE` | テープに何も入っていない |
| `NOT FOUND` | その名前のブロック(またはメモリのブロック)がない |
| `TAPE ERROR` | PX-65の形式ではない、途中で切れている、チェックサムが合わない |
| `TAPE FULL` | テープがいっぱいで保存できない(W。テープは保存前のまま) |

テープをファイルにするには、エミュレーターの「テープを保存」を押します。ファイルから読み込むには「テープを入れる」でファイルを選んでから `L` を打ちます。テープの中身はブラウザが覚えているので、ページを開き直しても残ります。

BASICの `FILES` で、テープの中身の一覧を見られます。

テープの形式(ブロックを続けて記録する。BASICと共通):

| バイト | 内容 |
| --- | --- |
| 0-1 | `"PX"`(`$50 $58`) |
| 2 | 種類。`$01` = メモリ(W)、`$02` = BASICのプログラム |
| 3-10 | 名前(8文字、足りない分は空白) |
| 11-12 | 開始番地(下位、上位) |
| 13-14 | 長さ(下位、上位) |
| 15- | データ |
| 最後 | チェックサム(このブロックの、それより前のすべてのバイトの和の下位8ビット) |

## 使ってみる

BIOSの CHROUT で「A」を表示して戻るプログラムです。`A` で打ち込みます。

```
*A 600
0600 LDA #41
0602 JSR FF00
0605 RTS
0606
*
```

`E 600 A9 41 20 00 FF 60` のようにバイトで書き込んでも同じです。`U 600` で確かめられます。

`G 600` で実行します。

```
*G 600
A
A=41 X=00 Y=00
S=FF P=..-B...C
```

「A」が表示され、RTS でモニターに戻ってレジスタが表示されます。

1命令ずつ追うときは、次のようにします。

```
*R PC 600
*T
*T
```

## プログラムから使えるルーチン(BIOS)

`$FF00` からのジャンプテーブルを JSR で呼びます。この番地は今後も変えません。

| 番地 | 名前 | 入力 | 出力 | 壊すレジスタ |
| --- | --- | --- | --- | --- |
| `$FF00` | CHROUT | A = 文字 | | なし |
| `$FF03` | GETKEY | | A = キー(押されるまで待つ) | なし |
| `$FF06` | KEYCHK | | キーがあれば C=1、A = キー。なければ C=0 | なし |
| `$FF09` | GETLINE | | `LINEBUF`(`$0300`)に1行(58文字まで)、`LINELEN`(`$0250`)に文字数。入力中のキーは「入力のしかた」と同じ(← → で動かす、挿入、DEL、↑) | A, X |
| `$FF0C` | PRHEX | A = 値 | 16進数2桁を出力 | なし |
| `$FF0F` | PRINT | JSRの直後に0で終わる文字列を置く | 文字列を出力し、その後ろに戻る | A |
| `$FF12` | BEEP | A = 高さ、X = 長さ | | A, X, Y |
| `$FF15` | CLS | | 画面を消してカーソルを左上に | A, X |
| `$FF18` | LOCATE | X = 桁(0〜15)、Y = 行(0〜3) | | なし |
| `$FF1B` | MONITOR | | モニターに戻ってレジスタを表示 | |
| `$FF1E` | GETLINE_ED | `LINEBUF` に文字、`LINELEN` に文字数 | それを表示してから続きを入力する(出力は GETLINE と同じ) | A, X |
| `$FF21` | MONENTER | | モニターのプロンプトに入る(BASIC の `MON`) | |
| `$FF24` | TSAVE | `T_TYPE` `T_NAME` `T_START` `T_LEN` | そのブロックをテープの最後に足す。C=0 保存できた。C=1 ならテープがいっぱいで、A = 4(テープは保存前のまま) | A, X, Y |
| `$FF27` | TFIND | A = 0 先頭から、1 続きから | 次のブロックの見出しを `T_TYPE` などに読む。C=0 見つかった。C=1 なら A = 1 テープなし、2 もうない、3 壊れている | A, X, Y |
| `$FF2A` | TLOAD | `T_START` | TFIND で見つけたブロックのデータを `T_START` から書き込む。C=1 なら壊れている(A = 3) | A, X, Y |
| `$FF2D` | CUROFF | | 点滅中のカーソルを消す | A |

- CHROUTの制御文字: `$0D` 改行、`$08` 1文字戻って消す、`$0C` 画面を消す。`$20-$7E` は文字。それ以外は無視します。4行目で改行すると画面が1行上がります
- GETKEYのキーコード: 文字キーはその文字、RET `$0D`、DEL `$08`、← `$11`、→ `$12`、↑ `$13`、↓ `$14`。キーはタイマー割り込みで読むので、GETKEY、KEYCHK、GETLINE は割り込みが有効(I=0)のときに使います
- BEEPの音: 半周期が約 5×A+12 サイクルなので、A=100 で約1kHz。X は鳴らす周期の数(1〜255、0は256)
- テープの見出しの番地: `T_TYPE` `$02A0`、`T_NAME` `$02A1`(8バイト)、`T_START` `$02A9`、`T_LEN` `$02AB`。`rom/px65.inc` に定義があります
- PRINTの例:

```
        jsr $FF0F
        .byte "HELLO", 0
        rts
```

## メモリの使い方

| 範囲 | 用途 |
| --- | --- |
| `$00-$7F` | ユーザー用 |
| `$80-$DF` | BASIC用(BASICを使わないならユーザー用) |
| `$E0-$FF` | モニターとBIOS用(`$F2-$F3` はタイマー割り込みの回数で、64Hzで増える) |
| `$0100-$01FF` | スタック |
| `$0200-$02C5` | モニターのワークエリア(キーバッファ、レジスタ、ブレークポイント、テープなど) |
| `$02C6-$02FF` | BASICのワークエリア |
| `$0300-$037F` | 入力行(`$0300`)と直前の行(`$0340`) |
| `$0380-$03FF` | BASICのワークエリア |
| `$0400-$057F` | VRAM |
| `$0580-$07FE` | ユーザー用。`R` のPCの初期値は `$0600` |
| `$07FF` | BASIC が使う(いつも0。BASICを使わないならユーザー用) |
| `$0800-$7FFF` | BASICのプログラムと変数(`$7FFF` は BASIC が `VAL` に使う。BASICを使わないならユーザー用) |
| `$8000-$80FF` | I/O |

### 割り込み

割り込みは、RAMに置いたベクタを経由して処理します。ユーザーのプログラムが割り込み処理を差し替えたいときは、ここを書き換えます。

| 番地 | 内容 | 初期値の処理 |
| --- | --- | --- |
| `$02C0` | IRQベクタ | タイマー割り込みの処理(キーボードを読む) |
| `$02C2` | BRKベクタ | モニターに戻る |
| `$02C4` | NMIベクタ | BREAKキーの処理 |

どのベクタも、割り込みが起きたときと同じレジスタとスタックの状態で呼ばれます(RTIで戻れる)。IRQを差し替えるときは、キー入力が止まらないように、元の処理へJMPでつなげてください。リセットするとベクタは初期値に戻ります。

## できないこと、注意

- ROMの中は1命令ずつ実行できません(BRKを書き込めないため)。T でROMのサブルーチンを JSR する命令に来たら、P と同じようにまとめて実行します。ROM へ JMP した場合は、そのまま続けて実行します
- 自分自身へ分岐する命令(`BNE *` など)は T で進められません
- `$00E0-$057F` へ進む命令は T、P で進められません(`?` になります。P の JSR は除く)。G でなら実行できます
- 入力行の先頭が画面の上に流れて見えなくなったとき(BASIC の `INPUT` の長いプロンプトの後に、58文字近く打ったときだけ起きる)は、見えている所より前には ← で戻れません
- 読み込む番地はモニターのワークエリア(`$0200-$037F`)やゼロページの `$E0-$FF` と重ならないようにしてください。重なるとモニターが正しく動きません

## ROMの作り直し

```sh
npm run rom         # BASIC とモニターをアセンブルして rom/px65.bin(内蔵ROM)を作る
npm run monitor     # モニターだけのROM(rom/monitor.bin)を作る
npm run samples     # 新しいROMでサンプルのテープ(samples/samples.tap)を作り直す
npm run build       # rom/px65.bin を内蔵ROMにして dist/ を作る
npm test            # モニターのテストを含むすべてのテスト(ROM、テープ、dist/ がソースと合っているかも調べる)
```

- `rom/font.s` は `tools/mkfont.js` が作ります。字形を変えるときは `tools/mkfont.js` の `GLYPHS` を直します
- `rom/optable.s` は `tools/mkoptable.js` が CPUコアの命令表(`src/cpu65c02.js`)から作ります
